Add (1 option)
  --naming-strategy full-path   [naming.qualify-shared-inline-names]
      Inline schemas under different parents share property names (names: 1, e.g. type x2; inline
      names equal to a component name: 0). Numbered names (Status, Status1) depend on parse order
      and shift when the schema grows; full-path names each inline model after its parent.
      measured: GitHub REST API description: numbered names 663 -> 53; locations renamed between two
      versions 17% -> 0.0%
      measured: Petstore: Status and Status1 became OrderStatus and PetStatus
      measured: Stripe API description: the expandable ID string of charge no longer displaces the
      charge component (ChargeModel)
      measured: SchemaStore workflow and tsconfig schemas: full-path doubled or lengthened names and
      lost

Known issues
  #4819 integer-enum-null-member (fails at import): An integer or number enum that lists null
      becomes an IntEnum or a value-typed Enum with a None member, which fails at import (integer
      enums with null: 1, number enums: 0). No single configuration avoids it together with #4882,
      so the command keeps it.
  #4882 optional-literal-discriminator (fails at import): A discriminator property that is a
      single-value enum or const without a default and not required becomes an optional Literal, so
      pydantic rejects the union at import; Enum classes avoid it for enum tags while no enum tag
      has a default (enum tags: 1, const tags: 0, enum tags with a default: 0). No single
      configuration avoids it together with #4819, so the command keeps it.
